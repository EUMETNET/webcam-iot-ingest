Checkpoint 4 work record - shared altitude enrichment
=====================================================

Status
------

Checkpoint 4 is accepted. Automated and bounded live validation pass. The
initial full live backfill is partially complete because
the public elevation service stopped resolving batches after exactly 5,000
sites; the remaining null values are deliberately retained for later retry.

Preparation completed
---------------------

- The private architecture altitude requirements were reviewed as read-only
  background.
- Windy webcam coordinates were confirmed to remain available in each
  source_stream.provider_metadata JSONB object.
- The Windy inferred-site colocation threshold was reduced from 100 metres to
  10 metres so one site-level terrain altitude remains a reasonable
  approximation for grouped cameras.
- Only the Windy registry was cleared, preserving other networks, and a fresh
  discovery was applied with the 10-metre threshold.
- That discovery registered 25,055 streams in 21,823 sites. Of those sites,
  2,112 contain more than one stream; the largest contains 14 streams.

Implementation
--------------

- discovery/shared/altitude_lookup.py implements bounded, paced Open-Meteo
  requests for at most 100 coordinate pairs, strict result validation, and
  retry handling for throttling and transient server failures.
- discovery/shared/add_altitude.py provides the standalone --network command
  with --dry-run, --limit, and --batch-size controls.
- Missing sites are selected deterministically by network. Existing altitude
  values are never queried or overwritten.
- Updates are guarded by site identifier, network, null altitude, and the
  original latitude/longitude, preventing stale-coordinate writes.
- Failed batches and null elevation values remain unresolved and eligible for
  later runs.
- Windy discovery preserves altitude while anchor coordinates are unchanged,
  clears it after coordinate movement, and invokes the same shared enrichment
  function after successful registry reconciliation.
- Windy discovery --dry-run performs no registry or altitude write.
- Configuration controls enablement, provider URL, timeout, batch size,
  request delay, bounded attempts, and a 5,000-site maximum per run.
- README records the required Open-Meteo and Copernicus DEM attribution.

Standalone command
------------------

The implemented interface is:

    uv run --env-file .env python -m discovery.shared.add_altitude --network win

It supports --dry-run, --limit, and --batch-size options. Dry-run does
perform real elevation lookups and validation but will not modify PostgreSQL.

Validation performed
--------------------

- 31 focused configuration, shared-discovery, and Windy unit tests passed.
- 15 live PostgreSQL integration tests passed.
- The exact bounded dry-run command selected and resolved 10 sites and updated
  zero rows.
- Two bounded applied runs resolved and updated 10 sites each. The second run
  correctly selected the next ten still-missing sites.
- The full pass saw 21,803 remaining eligible sites, resolved and updated
  5,000, and left 16,803 unresolved for retry.
- The registry now contains 21,823 Windy sites: 5,020 with altitude and 16,803
  without altitude. No site lacks latitude or longitude.
- Stored altitude values currently range from -2 m to 4,493 m.
- Python compilation and diff whitespace checks passed.

Operational finding
-------------------

The exact 5,000-result boundary is consistent with public-service rate or
quota enforcement. The free endpoint documents rate limits and no uptime
guarantee. The workflow behaved as designed: successful results were guarded
and stored, failed batches remained null, and a later run can resume solely
from the missing set. Normal standalone and integrated runs are now capped at
5,000 sites. The operational workflow intentionally uses one integrated
attempt per daily discovery. Already populated sites are not queried again, so
the current backlog is expected to drain over several days without consuming
the second half of the documented daily allowance.

Checkpoint decision
-------------------

Checkpoint 4 is accepted. Remaining null altitudes are an operational retry
backlog, not a checkpoint blocker: daily discovery retries up to 5,000 missing
values without re-querying populated sites. Image acquisition is checkpoint 5.
