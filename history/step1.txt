Pilot database schema
---------------------

Added database/schema/001_pilot_schema.sql with the three physical pilot
tables specified by the architecture:

1. network
2. site
3. source_stream

The schema includes:

- Primary and foreign keys.
- timestamptz timestamp columns.
- jsonb provider metadata constrained to JSON objects.
- Latitude and longitude range constraints.
- An uppercase two-letter country-code constraint when country is present.
- active, inactive, and blacklisted source-stream statuses.
- A nonnegative constraint for ema_download_period.
- Provider identifier uniqueness within its owning network or site.
- Indexes for network/site joins and due active-stream selection.
- Initial network rows for Windy (win), Fintraffic (fin), and Skaping (ska).
- Pilot renditions remain explicit source_stream values; discovery will later
  assign preview for Windy, full_jpeg for Fintraffic, and mini for Skaping.

Known validation limitation
---------------------------

Docker is not installed in the Codex execution environment, so the Compose
configuration, PostgreSQL initialization, schema integration tests, and MQTT
publish/subscribe check must be run by the repository owner using the separate
checkpoint validation runbook.

The repository's pre-existing upload test suite also currently imports
api.main before its MQTT mock takes effect. With no broker running, those
legacy tests fail with a connection-refused error during test setup. This is a
pre-existing test-isolation issue and was not changed as part of Checkpoint 1.
